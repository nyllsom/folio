# 写作规则

将给定材料整理成可以独立阅读的图文讲义。遵循用户指定的语言、范围与用途；以下为默认要求。

## 正文

1. **自包含。** 直接解释概念、理由与关系，读者无需查看原材料。避免“原课件指出”“如前面所说”“后续章节会讲”等依赖外部上下文的表述。必要背景在当前位置简要补足。
2. **简明而完整。** 保留关键定义、因果关系、区别、条件、例外和有助理解的例子；删去重复口号。公式需解释变量、单位与成立条件。可以补充可靠的必要背景，不得编造事实、数据或出处；关键歧义先核实。
3. **首次出现的术语写全称。** 使用中文术语或缩写时，在整份正文首次出现处附完整名称，例如“往返时间（Round-Trip Time，RTT）”；后文用中文或缩写即可。不要为本来不是缩写的名称杜撰展开形式。各章分批写作时沿用已有术语记录。
4. **以自然语言段落展开。** 每段围绕一个主题，用完整句子连接论点、解释与例子，可以适当分段和加小标题。仅在步骤、并列项目或对比确实更清楚时使用列表、表格，避免把 slides 的项目符号直接搬过来。

## 图片与来源

选用能帮助理解的原图，保留必要标注，裁去无关装饰。正文解释图中关系，图注说明读者应观察什么，避免“见原图”或只写页码。检查图片清晰度以及图中文字、符号与正文的一致性。

来源、页码映射和新增参考资料集中记录于 `SOURCES.md`，不把溯源话术写入学习正文。保留必要的署名与许可信息，不因裁图或改写抹去应保留的信息。

## Markdown 约定

一个 `#` 表示文档标题；每个 `##` 开始一页；`###` 表示页内小标题。长页可以滚动，按知识主线分页，不按屏幕字数强行拆分。

图片使用相对稿件的本地路径，独立成段；可选 title 作为图注：

```markdown
# 文档标题

## 一个完整主题

直接进入解释正文。

![图片的文字描述](assets/figure.png "帮助理解图意的说明。")

### 页内小标题

继续展开相关细节。
```

使用编译器支持的 Markdown，不嵌入原始 HTML 或远程图片。当前未提供数学公式排版引擎，简单公式使用可读文本或行内代码；复杂公式使用清晰的本地图片并在正文解释。

文件从标题开始，不写“以下是整理结果”等对话引言。交付前逐项检查：独立可读、细节和条件齐全、术语首次写全、自然段落、图文一致、路径可用、来源有记录。
