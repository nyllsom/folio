# 把材料变成阅读页

欢迎，Agent。先弄清楚用户想读什么，再开始装订。

从对话、附件与工作目录确认输入、转换范围和输出位置。信息已足够就直接做；缺少输入或目标时，只询问缺失的部分，例如“这次要把哪份材料变成 HTML？”不要重复确认已明确的要求。

## 工作流程

1. 读取一次 [写作规则](slides-to-pages.md)。先提取材料的文字、目录与图片索引，保存到内容目录的 `.work/`，后续复用。扫描页、公式和图表需结合原页图像核对。
2. 根据材料的主线划分阅读页。优先沿用有意义的章节或 roadmap，每个 section 对应一个 `##`；多个要点应连成解释，不必逐张复制 slides。
3. 按章节读取相关原文与图片，写入 `pages.md`；插图存入 `assets/`。来源、原页码及图像对应关系另存 `SOURCES.md`。发现无法从材料确定的关键事实时，先核实或询问，不用猜测填补。
4. 运行 `folio bind pages.md -o pages.html`。默认使用 NJU；用户需要其他外观时再读 [主题与语法参考](../examples/reference.md)。未安装 CLI 时，在工具仓库运行 `node src/cli.js bind <稿件路径>`。
5. 检查正文是否符合写作规则，并在浏览器检查图片、公式、长页滚动、翻页及窄屏布局。发现内容或排版问题后修正并重新编译。
6. 交付 HTML、Markdown 和相关资源的路径，简要说明转换范围及尚未解决的问题。

## 少读、少重做

核心规则只在写作规则中维护，不必每章重复粘贴。需要措辞示例时再读 [改写示例](examples/rewrite.md)，需要完整稿件时再看 [可编译范例](../examples/quickstart/pages.md)。

大份材料逐章处理；不要反复把整份提取结果或图片编码输出到上下文。用 `.work/progress.md` 简记已完成章节、待核实事项和资源路径，便于继续工作。修改局部时只重写受影响的正文，最后重新编译整份 HTML。

这些步骤由 Agent 完成；`folio bind` 负责把整理后的 Markdown 编译成 HTML。
